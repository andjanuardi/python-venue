6. HTTP HEADER PATTERNS
================================================================================

6a. Stream Request Headers (from header_iptv field)
    Each channel specifies its own HTTP headers as a JSON string:
    {
      "Referer":    "https://source.domain/",
      "Origin":     "https://source.domain",
      "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:121.0) Gecko/20100101 Firefox/121.0",
      "Host":       "stream.worker.dev"    // (optional, for worker proxies)
    }

    Common patterns:
    - Some channels use "none" for all headers (open streams)
    - Some channels use specific Referer/Origin headers
    - User-Agent is sometimes randomized from a list in RC key "browsers"
    - Host header is specified when using Cloudflare Worker proxies

6b. License Request Headers (from header_license field)
    {
      "x-data": "none"
    }
    Almost all channels use {"x-data":"none"} for license headers.
    Some may include additional headers if needed by the DRM server.

6c. General Request Headers (from decompiled source code)
    These are constructed in BitTVActivity.java:
    - Referer : https://duktek.id/?device={deviceId}&is_genuine={flag}
    - Origin  : https://duktek.id
    - User-Agent: Randomly selected from a list in RC "browsers" config

7. DRM / LICENSE FLOW
================================================================================

7a. ClearKey DRM (58 channels in SP.json)
    - Stream type: "dash-clearkey"
    - HLS field contains .mpd (DASH manifest) URL
    - url_license contains base64-encoded ClearKey JSON:
        {"keys":[{"kty":"oct","k":"BASE64_KEY","kid":"BASE64_KID"}],"type":"temporary"}
    - The app likely:
        1. Fetches .mpd manifest
        2. Extracts ContentProtection > default_KID from MPD
        3. Uses the ClearKey (k) to decrypt the content
        4. Passes key to MediaDrm (ClearKey plugin or ExoPlayer)

7b. No DRM (2 dash + 17 hls channels)
    - url_license is empty string
    - Stream is played directly without decryption

7c. No Widevine DRM detected
    - All DRM channels use ClearKey (dash-clearkey)
    - No Widevine (CENC with L1/L3) headers or patterns found

9. NETWORK SECURITY CONFIG
================================================================================

File: base_config.xml
  - Trusts only system certificates (no user certs)
  - Uses cleartext (HTTP) traffic allowed (usesCleartextTraffic="true")

File: network_security_config.xml
  - Whitelists specific IPs/domains for cleartext (HTTP):
    103.30.123.46
    live.cnnindonesia.com
    live.cnnindonesia.com.cdn1.gotv.detik.com
    (and others)

This means HTTPS interception with mitmproxy cannot work because user
certificates are not trusted. All HTTPS traffic goes directly to servers
with system CA validation.

14. NOTES & FINDINGS
================================================================================

- Per-channel JSON (e.g. SCTV.json) does NOT exist in v215. The individual
  channel pattern appears to be from older v213_x builds.

- ID.json (and other country files) use a double-base64 encoding with P2 prefix.
  Decryption scheme (k0):
    reverse → Base64.decode → new String(UTF-8) → reverse → .getBytes(UTF-8)
    → skip non-base64 chars → Base64.decode → new String(UTF-8) → reverse

  P2 mode (patch_211): Files contain PREFIX + ENCRYPTED_DATA, where the prefix
  is patch_211_key + device_signature_hash + APK_CRC. The prefix varies by file
  (123-180 chars). The common hash "jhmfgfdgdvcgcghf519b491aa27f56..." appears
  in all country files as part of the prefix.

  Successfully decrypted: ID (81 ch), KR (32), MY (39), BR (99), FR (30),
  SG (33), AE (24), GB (33). RU, TR, UA return 404.

  New fields found in decrypted country JSONs (not in SP.json):
    - is_live ("t"/"f")     - is_movie ("t"/"f")
    - fake_event ("t"/"f")  - t_stamp (unix timestamp)
    - s_stamp (string)      - subtitle (string)
    - New jenis values: "ts" (Transport Stream), "dash-widevine"

- Premium channel list is behind Cloudflare - requires browser-like headers
  or Cloudflare bypass to access.

- ClearKey is the only DRM scheme used - no Widevine L1/L3 detected.

- All channels in the Sports TV list are free (premium="f").
  Premium channels may exist in the Cloudflare-protected premium list.

- The app randomizes User-Agent from a configurable list in RC.

- Stream URLs use a variety of CDNs, with some using Cloudflare Workers
  as reverse proxies to access geo-restricted content (e.g., DAZN).
